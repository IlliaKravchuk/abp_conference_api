# ABP Conference Booking API

RESTful API сервіс для управління конференц-залами, додатковими послугами та бронюванням з урахуванням складних бізнес-правил та тарифних зон.

## Архітектура
Проект побудований за принципами
 **Чистої архітектури (Clean Architecture)**:
- **Domain (`app/core`, `app/domain`)**: Бізнес-логіка, доменні моделі, Pydantic-схеми та ізольований калькулятор вартості оренди.
- **Infrastructure (`app/infrastructure`)**: Робота з базою даних (PostgreSQL) через SQLAlchemy 2.0, репозиторії.
- **Services (`app/services`)**: Сценарії використання (Use Cases) та перевірка бізнес-правил.
- **API (`app/api`)**: FastAPI контролери та маршрутизація.

## Вимоги
- Python 3.10+
- Docker & Docker Compose

## Швидкий запуск

1. **Клонуйте репозиторій та перейдіть у папки проекту.**

2. **Запустіть базу даних через Docker Compose:**

bash

docker compose up -d

3. **Створіть та активуйте віртуальне середовище:**

bash

python3 -m venv venv

source venv/bin/activate

4. **Встановіть залежності:**

bash

pip install -r requirements.txt

5. **Заповніть базу початковими даними (зали та послуги):**

bash

python seed.py

6. **Запустіть сервер:**

bash

git add README.mduvicorn app.main:app --reload

Доступ до інтерактивної документації Swagger UI: **http://127.0.0.1:8000/docs**


# Короткий опис проєкту (Бізнес-завдання та технічні рішення)

## Що за проєкт і навіщо він потрібен?
Я зробив RESTful API для того, щоб зручно управляти конференц-залами та бронюванням. Основна ідея — автоматизувати всю рутину, щоб система сама слідкувала за бізнес-правилами:
- **Зали**: можна додавати нові приміщення, змінювати їхні дані чи видаляти.
- **Бронювання**: система сама перевіряє, чи не перетинаються часи оренди, чи немає якихось конфліктів за розкладом.
- **Послуги**: до замовлення можна накидати додаткові опції (скажімо, обладнання чи кава-паузи).
- **Аналітика**: є готовий зріз даних, щоб бачити статистику по бронях та завантаженості залів.

## Як це все влаштовано всередині (технічна частина)
Для реалізації я обрав сучасний та зручний стек:
- **Python + FastAPI**: обрав FastAPI, бо він дуже швидкий і сам автоматично малює круту документацію (Swagger).
- **Архітектура**: розділив усе за принципами Clean Architecture (чистої архітектури). Окремо лежить бізнес-логіка (`Domain`), окремо робота з базою (`Infrastructure`), окремо сервіси та самі API-роути. Це робить код зрозумілим і легким для підтримки.
- **База даних**: PostgreSQL разом із SQLAlchemy 2.0 для надійного збереження даних.
- **Валідація**: Pydantic v2 слідкує, щоб усі вхідні та вихідні дані були правильного формату.
- **Docker**: підняв через Docker Compose, щоб база даних запускалася в один клік і не виникало проблем із середовищем.
